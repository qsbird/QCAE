# 架构决策、实施顺序与验收

本文补充 [架构总览](README.md)。以下ADR在设计基线1.0中接受；设计已确定不等于产品已实现或测试通过。

## ADR-01：单一本地engine宿主

决定：采用独立qcae-engine，GUI、CLI、MCP连接同一业务宿主。

驱动：GUI/AI并存、无窗口运行、唯一事务历史、GUI关闭后任务生命周期。

替代方案：GUI内嵌core，另设headless host。它对最早GUI演示更轻，但需要两种宿主/连接路径和核心迁移规则。

取舍：增加本地IPC、启动锁、重连和数据传输成本；减少双核心、双历史和GUI生命周期耦合。工程支持本机并不等于远程服务器部署。

后续：用启动/连接/GUI关闭测试证明价值；如果实际IPC成本不达标，优化批量通道而不是让GUI绕过事务直写。

## ADR-02：领域核心独立于第三方框架

决定：types/domain/contracts及业务服务不依赖Qt、VTK、SQLite、MCP实现。

替代方案：直接使用QObject、vtkDataSet或数据库行作为全平台模型，初期接线更少，但会把UI/显示/持久化生命周期带入业务。

取舍：需要适配和DTO转换；可以分别测试、更换显示或部署方式。P0不追求所有传输零拷贝。

后续：核心独立构建；架构检查禁止核心include第三方适配头文件。

## ADR-03：项目快照与工作恢复库分开

决定：用户的.qcae是手工保存快照；工作库持久化当前提交；RAM是已提交表示。

替代方案：直接把原工程作为每次编辑写入库，省文件但使未保存/放弃语义复杂。

取舍：更多磁盘和快照复制；P0可接受中小模型完整复制。必须处理保存替换成功但工作标记未更新的恢复窗口。

后续：验证另存、磁盘不足、保存中断及用户明确放弃修改；不假设两份数据库能天然原子提交。

## ADR-04：单文档单提交者，读取用快照

决定：一个串行文档提交队列；后台任务计算候选，提交时校验版本。

替代方案：多写者并发合并、任意模块直写。前者成本过高，后者破坏撤销与AI一致性。

取舍：大写操作会排队；读取/界面继续使用稳定快照。P0用可测的提交区与资源上限控制体验。

后续：故障注入检查COMMIT前后窗口；引用、历史、幂等与任务提交结果同事务持久化。

## ADR-05：AI是外部工具调用者

决定：MCP桥负责协议转换，场景知识和确定性规则在应用的analysis模块；外部AI负责语言交互与步骤选择。

替代方案：用屏幕自动化作为主接口，或让LLM直接改数据库/脚本。前者无法稳定无界面执行，后者绕过核心规则。

取舍：工具说明和结构化反馈需要设计；不需要自建聊天产品，不绑定模型厂商。用户数据去向由最终AI客户端/模型配置明确。

后续：既有AI-01—AI-10加上旧epoch/多客户端/重连测试。MCP桥不能成为第二个文档宿主。

## ADR-06：P0不预建亿级基础设施

决定：保留稳定ID、批量接口、可替换存储/渲染与分块边界，但不实现分布式、远程渲染和通用插件框架。

取舍：未来亿级需专门优化，不能保证换适配器即达标。P0优先证明模型语义和生命周期正确。

## 实施顺序

| 阶段 | 计划范围 | 退出条件 |
|---|---|---|
| M0 运行骨架与契约 | contracts、ipc_local、apps/engine、clients/cli | GUI/AI模拟客户端连接同一engine；并发启动不产生双实例；核心测试无Qt |
| M1 文档与组织关系 | domain、query基础、nastran_codec最小子集 | 多视角查询共享实体；跨INCLUDE引用一致；支持子集往返通过 |
| M2 事务与恢复 | commands/history、application提交协调、storage | AI幂等、版本、undo、各崩溃窗口、保存/另存通过 |
| M3 选择与GUI | query空间/范围、render_data、vtk、desktop | 隐藏/遮挡/穿透/反选准确；GUI和CLI共用数据/历史；基础交互响应可测 |
| M4 任务与分析 | jobs、analysis、validation、solver/result/artifact适配 | 真实悬臂梁求解及检查；取消/过期结果/恢复不破坏模型 |
| M5 外部AI | mcp桥、cantilever场景、结构化反馈 | 一个真实AI客户端全流程；GUI交替修改和统一undo通过 |
| M6 集成发布验证 | 目标OS构建、资源与格式兼容、联合回归 | 中小模型基准、部署、无窗口和重连均有证据 |

文档、事务和持久化接口需从M0/M1共同确定；M2才补齐故障实现不意味着先绕过事务大量开发UI。这里只列计划源模块，当前仓库尚无这些源码。

## 架构验收矩阵

| ID | 验证方式 | 必须满足 |
|---|---|---|
| AR-01 核心纯净 | 禁用Qt/VTK/SQLite/MCP后构建核心与内存适配测试 | 模型读写逻辑、命令、查询与撤销测试可执行 |
| AR-02 单一宿主 | GUI先、AI先、同时启动、两个MCP客户端 | 同工程只有一个可写文档及历史；连接同一engine |
| AR-03 项目锁 | 同路径及路径别名重复打开，模拟异常退出 | 不产生两个写入者；残留锁不被无验证删除 |
| AR-04 事务故障 | 在准备、DB提交、RAM发布、响应之间注入故障 | 模型/引用/历史/幂等保持一致，已提交重试不重复 |
| AR-05 重开与重试 | 正常打开、故障恢复、undo后重试、旧任务完成 | 新打开不继承活动幂等空间；故障恢复保留原操作；旧epoch/任务不写新文档 |
| AR-06 保存窗口 | 备份中断、替换后崩溃、另存失败、另存后身份核对 | 旧或新完整快照可辨认；目标与工作库ProjectId/保存内容一致；纯另存不新增模型修订或undo |
| AR-07 选择一致 | 相机变化、隐藏/遮挡、多对一渲染ID映射 | 真实实体准确；无图形能力不静默改变选择语义 |
| AR-08 任务产物 | 取消、启动后崩溃、PID复用、缺失产物 | 不凭退出/文件存在认定成功，不无依据再次启动 |
| AR-09 结果溯源 | 求解中改变物理输入，再仅改变相机 | 前者旧结果标记非当前；后者结果继续适用 |
| AR-10 无窗口流程 | 未启动GUI执行悬臂梁完整流程 | 不需要模拟点击或OpenGL来完成模型与求解步骤 |
| AR-11 数据配额 | 批量选择/历史/任务临时文件超限 | 明确拒绝或受控失败，模型无半修改，不无限扩张队列 |
| AR-12 客户端重连 | 丢弃事件、断开响应、GUI关闭但任务继续 | 状态可重同步，副作用不因重连重复 |

另执行 [AI场景验收](../P0-AI验收用例-v0.6.md)。实际性能阈值须以选定机器和模型分档确定；此文没有虚构FPS、延迟或容量测试结果。

## 按开发阶段落实的环境门禁

具体首发系统、Nastran方言/求解器、外部AI客户端、历史/恢复配额以及中小模型分档。它们影响适配器与验收数据，不要求推翻核心模块设计。

本轮架构审查仅针对文档、依赖和失败路径，真实编译、IPC、数据库恢复与求解器测试留在实施阶段。


## 本轮审查修订

独立审查后补齐：SaveAs预先固定身份/内容且不增加模型修订；任务提交校验DocumentId/Epoch/Revision；正常打开与恢复的DocumentId/幂等继承区别；render_data明确为engine生产端，GUI和图像进程只消费公共RenderPacket。上述是文档审查结果，尚未通过运行测试。


## ADR-07：统一操作描述与明确转换/失效语义

决定：吸收参考研究的OperationDescriptor、ImportReport/ExportReport和ChangeImpact，分别归入contracts/application、格式适配/validation、commands/analysis；不增加大型生成器或通用重算框架。

理由：减少GUI/API/AI语义分叉，防止格式静默丢失和陈旧结果误用。

验证：操作描述与实现一致；不支持卡片不静默导入；共享属性/集合改变按引用传播影响；纯视图改变不使求解结果过期。

当前稳定测试ID和需求追溯见[验收基线](../baseline/acceptance.md)，M0任务切片见[开发计划](../baseline/development-plan.md)。
