# ADR-10：Gmsh 平面网格适配器

日期：2026-10-20。状态：适配器已实现（G1）；接入engine和平板几何/网格操作属于G2。范围与状态以
[开发计划](../baseline/development-plan.md#当前工作轨道平板网格流程)为准。

## 驱动

QCAE是开源、非商业的学习项目（2026-10-19用户决定）。平板网格轨道要求一条从几何到数值验证的完整流程，代码以清晰为先。内置的一维均匀网格不能划分带孔平板；[需求](../baseline/requirements.md)约定自动网格“需要时再接入已有组件”。QCAE按WTFPL发布，可以与Gmsh的GPL-2.0-or-later（含链接例外）组合分发。

## 决定

- 只引入Gmsh。从源码构建固定版本4.15.2（`gmsh_4_15_2`，`657c8e9`），`-DDEFAULT=0` 后只开网格模块、Eigen和TinyObjLoader，不含GUI、OCCT和OpenMP；库只链接C/C++运行库。构建步骤见[适配器说明](../../adapters/mesher_gmsh/README.md)，本机构建来源记录在安装前缀下的 `PROVENANCE.json`。
- 核心只定义纯数据端口 `IPlanarMesher`（`modules/contracts`）：输入是直边外环和孔围成的平面区域、单元尺寸和三角形上限，输出是节点、绕区域法向逆时针的三节点三角形，以及每条输入边上的边界线段。同一输入必须得到同一网格；`identity()` 给出网格器和版本，供网格记录来源。
- 区域是否有效由核心判断：`measure_planar_region`（`modules/planar_geometry`）检查角点、共面、边不相交也不相触、孔在外环内且互不包含，并给出法向和面积。Gmsh 4.15.2遇到自交外环、与外环共边的孔、两个相同的孔时会挂起不返回，所以只有有效区域才交给Gmsh。G2的平面几何实体规则复用同一检查。
- 适配器 `GmshPlanarMesher` 在engine进程内调用Gmsh的C++ API：
  - Gmsh的模型和选项是进程全局状态，所有调用持同一把锁；
  - 构造时启动一次Gmsh，不读用户配置、不向终端输出，并复原Gmsh启动时改动的 `PATH`、`PYTHONPATH` 和进程locale。4.15.2的帮助列出 `-noenv`、`-nolocale`，但其命令行解析把两者当作未知选项并退出进程，因此改为事后复原；复原不是线程安全的，宿主须在启动阶段、其他线程运行前构造适配器；
  - 每次调用由作用域对象删除自己建的Gmsh模型：失败后Gmsh会把失败的模型保留为当前模型；
  - 只取面及其边界上的节点（几何辅助点也会得到节点）；三角形统一转为绕区域法向逆时针，并核对总面积；
  - 运行中的网格不能中断，所以按“边长不短于单元尺寸”的面积估算在开始前拒绝超限请求，网格后再按实际数量检查。很多短边（如细分的圆孔）会让网格远比估算细，这时超限请求要等网格完成才被拒绝。
- 可选构建：`QCAE_WITH_GMSH=ON` 和 `QCAE_GMSH_ROOT`（本机配置，CMake只在该前缀查找），默认关闭；纯核心的构建与测试不需要Gmsh。架构门禁把Gmsh视为框架依赖，核心目标不得包含或链接它。

## 替代方案与取舍

- 独立网格进程：崩溃隔离、可杀进程取消、可加超时，但要多写进程管理和数据格式。学习规模的平板网格在一秒级内完成，已知会挂起的输入已由区域检查排除，因此先在进程内实现；端口不变，日后改为进程外只需替换适配器。
- 调用 `gmsh` 命令行并生成 `.geo` 脚本：脚本是一门语言，拼接用户输入有注入风险，还要解析 `.msh` 文件。
- Debian的 `libgmsh` 包：会带入FLTK、OpenGL、X11和OCCT，版本随发行版变化，不利于跨平台固定。
- Netgen加OCCT：两个依赖，而平板网格不需要CAD内核。

代价：Gmsh在engine进程内崩溃会让engine退出，已提交状态由工作库恢复；挂起只对已知的无效拓扑做了预防，有效区域上仍可能有未知的长时间运行；分发链接Gmsh的engine二进制时，二进制属于GPL下的组合作品，QCAE源码仍按WTFPL。不由此声明一般性能或大规模网格能力。

## 验证与后续

- `planar_geometry`（核心测试）：有效形状的面积和法向；坏角点、翘曲平面、相交或相触的边和位置错误的孔都被拒绝，包括会让Gmsh挂起的三类形状。
- `gmsh_planar_mesher`（`QCAE_WITH_GMSH=ON` 时构建）：面积覆盖、朝向、孔、边界线段、同输入同网格、拒绝与上限、并发调用、启动后环境和locale不变；删去复原步骤的变异会使该测试失败。
- 试运行记录在仓库外：约5千、4.4万、17.4万个三角形分别用0.09、1.3、6.8秒。
- Gmsh抛出异常后的模型清理目前只有试运行证据：还没有能通过区域检查、又让Gmsh抛出异常的测试输入。
- G2把适配器接入engine组合，新增平板几何实体和网格操作；关闭 `QCAE_WITH_GMSH` 时这些操作登记为不可用。
