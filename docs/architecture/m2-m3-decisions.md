# M2/M3 实施取舍

日期：2026-09-26。延续基线1.1核心、适配和客户端边界；以下说明当前小模型实现及尚未完成的目标，防止用运行成功掩盖验收缺口。

## 单工作槽的宿主登记与工作库

M2把宿主生命周期记录和当前工作文档保存在同一 SQLite 事务的版本化状态封装中。这样 create/open/close 的登记和工作文档状态原子提交，省去设计原型中“独立登记库＋每文档库”的跨库协调。正常打开建立新DocId，恢复原工作槽保留DocId；宿主事实有明确数量上限。此决定适用于P0单活动文档；未来多工作库/多文档不能直接沿用单槽假设。

状态封装中的当前模型完整编码，历史按实体差量编码。存储端口对状态内容不做业务解释，负责CAS代际、事务、锁及快照发布；纯核心负责格式版本、关系/配额、历史重放校验和目标能力。当前每次提交重写有界状态负载，尚未实现按数据库页/实体块增量存储，不能据此推断大模型性能。

## 明确保存与恢复

工程快照由已冻结模型新建独立SQLite数据库，验证后在同一文件系统原子替换并刷新，不复制活动主库。工作库保存意图与工程保存token用于恢复核实。替换之后但保存标记之前发生故障时，不能报告整个操作回滚。

锁按规范路径和文件身份隔离；本机SQLite与直接flock同一数据库inode有冲突，因此用保持目标描述符的私有dev/inode guard文件协调QCAE写入者。原inodeguard在原子替换后保留到租约结束，覆盖已有硬链接。独立副本不因相同ProjectId被无条件禁止。

## 只读显示投影与暂存会话

M3新增纯RenderPacket契约、engine侧producer和GUI侧VTK消费者。GUI只持有显示投影与表单草稿，保存/修改/历史均经过IPC应用服务。ViewSession与SelectionHandle是可丢弃、有配额的会话状态，不进入模型undo或SQLite内容状态。

临时选择采用随机服务代号加序号；句柄绑定调用者及模型/视图版本。选择数量上限后先清理过期记录，再淘汰最旧句柄；淘汰不改变模型，访问旧句柄明确报错。模型操作不会受另一窗口的隐式全局相机/选择影响。

当前真实GUI拾取在VTK中完成，核心校验明确候选和版本。无界面visible_only没有图形端口时保持不支持；将来接入同契约的离屏图形服务，不能将穿透查询当作遮挡查询。

## 暂时的运行边界

JSON RenderPacket和轮询只用于当前受控小模型工作区。二进制分块、序号化事件、布局恢复和多规模性能基准仍属于M3后续验收工作。程序有实际Qt/VTK渲染与交互证据，不宣称大规模网格达标。构建依赖隔离在被忽略目录，纯核心仍可以同时禁用Qt、VTK和SQLite。
