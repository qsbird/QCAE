# C1 数据核心检查点

C1 替换权威文档、提交/历史、记录存储和迁移实现，保留原引擎 IPC 与桌面入口。操作注册、参数和任务模块的可执行底层实现随此提交保留；对外 typed 引擎路由和六次工作流在 C2 提交接入。

## 验证

独立导出的 C1 源树以 Release、Qt/VTK/SQLite 全开构建；CTest 最终 **34/34**，包括旧核心、IPC、桌面 smoke、生成契约、8 项 schema 反例、10 种注册顺序、6 份旧格式迁移、记录存储、任务及历史验证。SQLite 任务测试输出真实成功/取消/过期各 10 个样本，节点编辑后 100 轮 undo/redo 精确增加 201 个修订。

CMake 实际依赖和生产文件归属门禁通过。运行明细见 [完整测试输出](evidence/c1/detailed-tests.log)、[最终汇总](evidence/c1/final-tests.log) 和 [构建边界报告](evidence/c1/architecture.json)。这不是 SK-01—14 全部通过声明。

## 审查

权威状态为 DocumentView；EditSession 只准备候选；RecordApplication 检查调用者、DocId/Epoch/Revision、幂等和配额后，向 IRecordStore 发布一个批次，再切换当前视图。历史使用稳定记录键与不可变前后镜像。旧 Model 只在兼容导入/导出边界出现。SQLite 行批次同时保存文档、历史、操作事实及已注册的辅助记录。

已修正内部 execute 失败泄漏预览配额、确定任务状态写入失败无法协调恢复、旧材料预览与 typed 操作的极小数单位校验分叉。六份旧夹具按完整模型与引用比对，源哈希保持不变；只读迁移在隔离副本中处理 WAL，并检测读取期间源变化。

## 历史失败保留

初次全量运行出现一次 SQLite 跨进程锁测试子进程退出断言失败，见 [原日志](evidence/c1/initial-tests.log)。保留原断言并增加具体 case/退出状态诊断后，192 次针对性执行均未复现，最终全量运行通过。原因仍未定位，诊断增强不等于已经修复该故障。另一项只读夹具的空 WAL/SHM 预设问题通过显式构造无侧车临时夹具解决；冻结源与产品只读要求未放宽。
