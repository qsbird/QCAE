# C3 display / Nastran slice readability review

This is a source review and bounded verification record. It does not mark SK, C4, solver execution, real AI, or full P0 accepted.

## Authority and side effects

`modules/query/src/render_projector.cpp` consumes immutable record versions and directed committed changes. `adapters/engine_api/src/render_service.cpp` publishes a versioned packet/delta as a resource. `adapters/transport_local/include/qcae/render_wire.hpp` validates the binary version and values before returning owned decoded data. `adapters/rendering_vtk/src/vtk_view.cpp` checks the complete delta before modifying any arrays. `ui/desktop/src/desktop.cpp` fences replies by document, epoch, revision, view version, and request generation. Ordinary row refreshes use stable-ID indexes; input forms do not enumerate the model in the background.

Hidden point/line entities retain stable render positions. Hidden nodes still supply beam endpoints. Visibility changes update affected cell blocks, while ordinary coordinate changes retain actors and unrelated arrays. Full resynchronization remains explicit. Picker and through selection exclude hidden primitives. The common render carrier supports bounded variable-arity polylines and polygons; production Line2 follows that carrier. No persistent triangle type or extension is introduced. VTK maps mixed line/area cells in its actual line-before-polygon ordering and retains stable entity identities. The existing eight point/line PICK cases have a frozen JSON fixture and hash; generic synthetic area tests do not constitute Tri3 evidence.

Wire v1 and v2 remain readable. A client without the new handshake capability uses resources expressible in versions 1/2, including actual Line2 full packets and visibility deltas. An area cell requires explicit wire-v3 negotiation and otherwise returns unsupported, including a guessed empty baseline after a rejected full request. MIME and magic must agree. Future versions, duplicate indexes/IDs, malformed fields, stale versions, and truncated/trailing bytes are rejected. Only a client that accepts the advertised inline-empty capability requests a version-only acknowledgement. It carries the exact document, epoch, from/to model revisions and view revisions, and goes through the original VTK atomic delta checks, GPU completion, tree updates and late-response fences. Other clients retain the pinned-resource path.

The lean refresh path requires three independent advertised capabilities. A strictly parsed continuous same-document summary uses the same context application function as project.current. Rebase checks the stored model and view bases before calling the existing SelectionService update; it preserves hidden/camera intent and advances the view exactly once. Only the exact predicted target acknowledgement/manifest is admitted. Wrong or unknown server versions recreate the disposable view, and stale current/resource callbacks retain their generation fences. Complete bounded entity rows use the same immutable render snapshot and production serializer, and the common row application function publishes them only after VTK installation. Missing capability, malformed summary/rows, queued camera work, topology/reference changes and explicit resynchronization retain the original fallback.

`model.export` is registered by `adapters/engine_api/src/nastran_contribution.cpp`. It validates the explicit installed profile, prepares a controlled Nastran plan, and freezes analysis identity, document version, physical signature, and export-number mapping through `features/analysis/include/qcae/analysis_input.hpp`. The `TaskService` queues real work. The initial task and file-publication intent are persisted together before any file staging starts.

`adapters/artifacts_local/src/artifacts_local.cpp` owns filesystem effects. It writes a new directory exclusively, stages and fsyncs files, rereads lengths and SHA-256 values, then publishes a manifest marker last. `profiles/nastran/src/nastran_package.cpp` independently imports the staged and published BDF/INCLUDE resources and compares their physical-card semantics against the frozen plan. Existing directories are not overwritten. Partial, missing, changed, cancelled, or unverified files cannot become successful publication evidence.

SQLite and the filesystem have no shared atomic commit. A verified manifest may exist before the final database acknowledgement. The durable intent permits explicit reconciliation; it does not authorize blindly rerunning export. Reconciliation checks current files, principal, request semantics, and eligible interrupted/unknown task state. Its request fact, recovered artifact fact, and recovered task completion are written in one owned-row batch. Same-key replay returns the original request fact and separately reports whether files are currently intact. A previously successful task does not append another success event.

`modules/runtime/src/task_record.cpp` retains the ordinary model-task contract: success needs a real `ChangeReceipt` and advanced model revision. File-only completion instead requires exactly one `TaskArtifactReceipt`, containing artifact identity, the original input revision, and a lowercase SHA-256 manifest digest. Only artifact-backed interrupted/unknown tasks can reconcile to success. Artifact receipts encode as schema 3; ordinary tasks keep schema 2; schemas 1 and 2 remain readable.

Explicit `project.migrate_profile` transforms a protected old candidate before activation. It verifies the exact old triple and installed new triple and rebinds analysis/source records through a prepared application change. Ordinary open retains the installed-profile gate. The source project is read-only, and migration has no inherited save target. New save-as establishes the new save point; recovery must preserve an unsaved migrated state.

## Static production contributions

The package has six working responsibilities, with no engine/Qt dependency in the pure profile header:

- Core rules: actual analysis-kind and source-number invariants registered with the record registry.
- Operations: typed export, artifact read/reconciliation, explicit migration, and UI descriptors registered with the host registry and a shared publisher coordinator.
- Codecs: the production controlled `NastranCodec` import/export and frozen export mapping.
- Validation: export capability checks plus independent disk-resource semantic readback.
- UI: the declared export contribution is consumed by the actual desktop action/form.
- Render: the package supplies actual Node, GeometryLine, and Beam projection callbacks to the production render service.

`ui/desktop/src/analysis_tools.cpp` is disposable input/check UI. All writes use the same declared operations and frozen document/epoch/revision context. Organization edits have distinct preview/cancel/apply controls. Unknown write outcomes retain their key, arguments, and input context for same-operation retry. Issue navigation rechecks the entity in the current version before selecting it; check reports retain their original version and become stale after model edits. A hidden form adds no background model queries and retains no shared row array that would force full cached-array detachment.

`ui/desktop/src/shortcut_preferences.cpp` changes only UI settings and action shortcuts. Stable action IDs persist bindings independently of display labels. Invalid/duplicate sequences are rejected before changing an action. The workflow test uses the actual preference form, then closes/reopens the window to check restoration and unchanged model revision/history.

## Instrumentation review

Binary Writer growth and appends count the single owned output buffer once. It has no additional owned metadata container, so encode metadata is explicitly zero. Reader string ownership is classified once: document/epoch/view strings as metadata, entity IDs as model payload. Validation/move-copy bounds are conservative and do not count the same copy in both classes. Qt JSON object creation is observed at its own builder in written insertion order; nested shared objects are not recursively recharged by parents or socket send. An inline empty acknowledgement explicitly covers only the absent binary/resource work; its actual JSON, UI, VTK and text work remains in the same operation ledger. The VTK upload observer accounts for audited CPU packed-coordinate copies using actual upload timestamps and records GPU bytes separately. Every actual desktop log append now observes the QPlainTextEdit piece-table mutation, including warm-up and operation failures, with public before/after character counts guarding its tracked shape. A new-line/control separator or unexpected mutation leaves that accounting unknown. Repeated font/text-layout ownership remains an unclosed SDK boundary. Unsupported/unreviewed library paths retain unknown coverage.
