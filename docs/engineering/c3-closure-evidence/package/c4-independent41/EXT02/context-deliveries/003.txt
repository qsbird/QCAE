# M0 实现与运行说明

本文记录 M0 交付时范围与测试结果；当前扩展能力见 [M1说明](m1.md)。

M0已经形成第一条真实运行链：CLI → 本地engine → 内存文档 → 材料参数预览/提交 → undo/redo → 查询。

**这是材料对象的内存切片，不是完整P0。** 不支持工程保存/恢复、BDF、Nastran求解、GUI或真实AI客户端；engine退出后数据丢失。接口和握手都返回`durable=false`。后续按既定M1—M6补齐能力。

## 已实现范围

| 任务 | 实现证据 | 限制 |
|---|---|---|
| M0-01 | C++20 CMake核心目标、严格警告、CTest入口 | 核心仅依赖标准库/线程；Python只用于构建生成与测试 |
| M0-02 | 从27项设计操作目录生成C++描述；强ID、Quantity、ProfileRef、TargetBinding、IProfileProvider元数据接口 | 生产Nastran profile尚未配置；描述目录不代表27项都实现 |
| M0-03 | 创建一份文档、材料创建/弹性模量修改、规范化单位、预览、原子提交、幂等、线性历史与快照 | 文档只含最小材料对象；有限数量配额；历史只在内存 |
| M0-04 | QtCore/Network engine与CLI；端点锁、握手、两个客户端共享状态、自动启动 | 单实例以同一本地端点为范围；尚无工程文件写锁 |
| M0-05 | 断开重连、版本拒绝、重复请求、并发启动、协议异常回归 | 重连指engine仍存活；不是进程崩溃后的模型恢复 |

当前可调用：capabilities.list、project.create/status、model.summary、changes.preview/commit、history.list/undo/redo、operations.get的文档变更结果查询。其余操作明确返回UNSUPPORTED_CAPABILITY。

支持的领域命令仅为material.create与material.set_young_modulus。Young模量支持Pa/kPa/MPa/GPa并归一到MPa；必须为有限正数，溢出/下溢为无效输入。文档/材料名称最多1024字节。资源上限通过Limits提供；当前按数量限额，不是总RAM硬上限。

## 环境证据

本轮实际验证：macOS arm64、Apple clang 21.0.0、CMake 4.3.0、Ninja 1.13.2、Qt6 Core/Network 6.11.1。构建找到Python3 3.14.7，设计检查也可使用Python 3.10+。

Qt使用已有Homebrew安装，无新增依赖安装。Catch2未在已检查路径发现；M0采用小型C++检查程序与CTest，Release也保留断言行为。后续可按需要引入已规划的Catch2，不伪装本次使用了它。

## 纯核心构建

```sh
cmake -S . -B build-core -G Ninja -DCMAKE_BUILD_TYPE=Release -DQCAE_BUILD_IPC=OFF
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

关闭IPC时不会查找或链接Qt、VTK、SQLite、MCP。生成的operations.hpp位于构建目录，源头为docs/contracts/operations.json，禁止手改生成文件。

## 本地engine与CLI

本轮macOS/Homebrew实际使用的Qt前缀如下；其他机器按安装位置调整：

```sh
cmake -S . -B build-local -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQCAE_BUILD_IPC=ON -DCMAKE_PREFIX_PATH=/opt/homebrew/opt/qt
cmake --build build-local
ctest --test-dir build-local --output-on-failure
```

真实IPC测试需要操作系统允许本地套接字监听。Codex沙箱曾返回`QLocalServer::listen: Unknown error 1`；在获得本机测试执行权限后通过，不能据此把沙箱失败当作协议通过或绕过成模拟测试。

测试脚本当前支持Unix本地域套接字，因此CMake只在UNIX上注册IPC测试。本轮没有Windows构建/命名管道验收。

在仓库根目录建立私有的运行目录并以前台方式启动：

```sh
mkdir -p runtime/m0
chmod 700 runtime/m0
./build-local/qcae-engine --socket "$PWD/runtime/m0/engine.sock"
```

另一个终端查询能力：

```sh
printf '%s\n' '{"api_version":"1.1","request_id":"demo-1","operation":"capabilities.list","parameters":{}}' | ./build-local/qcae-cli --socket "$PWD/runtime/m0/engine.sock" --no-start
```

省略`--no-start`时CLI可按需启动同目录下的engine，或用`--engine`明确可执行文件。自动启动的engine在CLI结束后继续驻留；当前没有空闲退出策略，需明确结束engine，且会丢失其内存数据。

## 业务流程示例

每条JSON发送给CLI，返回的document_id/document_epoch/preview_id需要用于后续请求。请求ID每次不同；同一逻辑修改重试保留幂等键和原参数。

```json
{"api_version":"1.1","request_id":"create","operation":"project.create","idempotency_key":"create-demo","parameters":{"name":"Beam"}}
```

创建材料的预览参数：

```json
{"command":"material.create","name":"Steel","young_modulus":{"value":210,"unit":"GPa"}}
```

调用changes.preview需再携带文档身份与expected_revision。用返回的preview_id调用changes.commit，随后model.summary能读取归一化后的210000 MPa；history.undo/redo可以恢复/重新应用。完整可运行例子在tests/ipc_tests.py中。

`runtime.handshake`属于本地传输协议，不是业务操作目录。CLI自动握手并核对API版本和响应request_id。控制消息为UTF-8 JSON行；请求正文上限1MiB、响应整帧上限1MiB，超限明确报错或关闭连接；request_id最多128 UTF-8字节。
