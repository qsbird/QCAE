# SDK owned-copy observation — bounded execution plan

This work closes specific SK-12 copy-coverage gaps. It does not freeze C4 or claim full SK/P0 acceptance. The last selection regression baseline is build31: **61 passed, 0 failed, 0 skipped**, with original RED logs retained. Model, view, camera, hidden intent, selection, resource lifetime and history behavior must remain unchanged.

## Public hooks

`sdk_copy_observation.hpp` defines an operation-bound read-only snapshot with component, actual calls, nullable byte bound and unsupported reason. `desktop_sdk_copy_observation(window)` and `VtkView::sdkCopyObservation()` retain only the last active operation. Reporting allocations do not enter model-payload counters. An absent ledger produces no measured run; unsupported is sticky within a run.

| Boundary | Actual hook and supported proof | Remaining boundary |
|---|---|---|
| Tree | Original QStyledItemDelegate paint/sizeHint/initStyleOption calls; QString DisplayRole without newline shares the existing UTF-16 payload | Non-QString or newline conversion, native style/font layout and paint remain unknown |
| Log layout | Original virtual blockBoundingRect/documentChanged; guarded Qt 6.11.1 branches count source-proven fresh QTextBlock::text payload | Nonvirtual ensureBlockLayout, font/glyph buffers remain unknown |
| Log paint | Original QPlainTextEdit paintEvent entry/calls; the observer performs no additional block traversal | Original paint traversal/preedit and fresh text bytes remain unknown at the public boundary |
| VTK mapper | Original OpenGL mapper virtual entry points; actual cache-state comparisons; point and plain Line2 index writes and conservative initialized-prefix relocation | Other attributes, polygon/strip/edge/vertex paths require separate observers |
| VTK VBO | Actual upload-time changes, deduplicated shared vertexMC VBOs; two owned float3 buffer writes and actual GL upload argument bytes | Range/shift and other native buffers require separate proof |

Public component facts are independent evidence. A library metric marked unknown cannot be silently excluded from a complete copy sum. Zero calls on an inactive component differs from evidence that every SDK path has been covered.

`qt_widget_copy_probe.cpp` compares the real original and observed text/tree rendered pixels and contents, including Unicode. It protects actual hook calls, inactive behavior, newline detachment and honest font/paint unknowns. Its exact-version test-only private SDK view also verifies that an offscreen block with no owned QTextLayout object remains uninitialized after base and observed paints. This view reads the existing pointer; it never calls the lazy `QTextBlock::layout()` getter. Root owns its build and GUI execution, followed by the full selection regression. The original causal fixture failure is retained: public `clearLayout()` clears line layout but retains the owned object; the corrected fixture mirrors the source's owned-pointer destruction on both remote blocks. Strict syntax checks of both production translation units and the probe have passed; the corrected runtime guard is pending.

## Exact-source Qt observation

`tests/prepare_c3_qt_sdk_ledger.py` prepares an isolated `build-c3-qt-observed/` source/build/prefix. It validates official qtbase 6.11.1 archive SHA-256 `d9594a31228aa23ad6b531719a29b45f0f3989fe6c136d45767ea179f233c1ac`, restores owned patch inputs from that archive, records original/instrumented hashes and compares required features against the installed headers. It neither replaces nor installs into the global SDK.

The test build uses Release, arm64, Cocoa/frameworks, Core/Gui/Widgets/Network/OpenGL/OpenGLWidgets, system HarfBuzz and FreeType, ICU and linked OpenSSL. Source instrumentation is observational: original calls and outputs execute once. Real function entries delimit text/model work; explicit bulk copies/writes, POD repetition and initialized-prefix growth record their logical byte arguments. Glyph LayoutData relocation uses the source's prior logical storage field, without querying allocator footprint. No predetermined number of Qt copy sites is treated as a completeness claim.

QtCore exports a C ABI observer installer and exact source manifest. It accepts a callback `(void *context, const char *site, unsigned kind, uint64_t bytes)`: kind 0 actual entry, 1 copy upper bound, 2 write upper bound, 3 unsupported. The callback must not throw, own Qt objects or be installed during measurement. Source-level facts and public byte bounds must be kept separate to avoid charging the same text twice. Root will gate any observed QCAE mode on the actual loaded manifest, not the Qt version string alone.

The first source tranche covers QTextBlock::text, actual layoutBlock/begin/end/draw/drawCursor, engine validate/shape and glyph growth, delegate/style elision and native CoreText entry points. Further exit evidence is required for every indirect container copy, generated store loop, glyph write and shaper buffer found in source/IR. System HarfBuzz 14.4.0 internal payload moves and CoreText's opaque internal buffers remain separate gaps until those exact boundaries are audited or observed. Successful compilation alone cannot close them.

The installed VTK Qt glue uses absolute Homebrew Qt framework paths. An observed QCAE must use an isolated copy or rebuild of that glue and verify actual loader paths, otherwise two Qt installations could enter the process. The global VTK/Qt installation stays unchanged. Root owns the QCAE CMake wiring, loader gate and native GUI validation; this agent may build only the isolated Qt source with at most two compiler threads.

Exit evidence consists of source/patch manifests, required-feature comparison, actual loaded framework paths, observed site calls/byte bounds/unsupported entries tied to the same operation, original-versus-observed output equivalence, the full selection regression and new raw end-to-end ledger samples. Any remaining unknown or budget failure remains visible.

## Actual source-build evidence and next tranche

The first isolated Qt prefix has been built and installed locally. The root's `qt_source_copy` CTest passed 1/1 in 2.83 seconds with the exact loaded source manifest and an isolated VTK glue copy; that prefix remains frozen. The public widget causal guard and the root's source-to-operation collector have separate runtime checks and cannot inherit this probe's pass. Generated feature comparison retains two differences, pkg-config and Vulkan, rather than claiming full installed-SDK equivalence.

The independent HarfBuzz 14.4.0 tranche uses official archive SHA-256 `2357ed966c6ced7bfa720b0640c0231065af01158fbea215093ffa15aed44371`. `prepare_c3_harfbuzz_sdk_ledger.py` produced 289 entry/bulk/logical-growth sites in 34 source files and built an isolated Release library, without changing the first Qt prefix or the global library. `harfbuzz_source_copy_probe.py` actually loaded both installed and observed libraries. The actual shaper lists match (`graphite2`, `ot`, `coretext`, `fallback`); 15 default/OT/CoreText cases preserve glyph ID, cluster, mask, advance and offset for English, Greek/CJK, Arabic, Devanagari and emoji. The report records 1,539 actual entry calls, 46 reached sites, 73,622 bytes of known bulk/write bounds and 15 explicit unsupported typed-store entries. This is output-equivalence evidence, not complete font-copy coverage.

The next isolated source tranche must add the real history piece-table insertion/append entry scopes, typed glyph and cache writes, and nontrivial container copies found in source/IR. It must bind the observed HarfBuzz image and preserve these remaining native ownership gaps. The first prefix must not be mutated to implement that tranche. Each closed boundary needs source anchors, actual call/byte evidence, original-output equality and a manifest change; a generic successful shaping call cannot close all glyph/cache writes.

## Actual second/third tranches and remaining scope

The second isolated Qt prefix and its bound observed HarfBuzz library have now run 20 real N=1000 end-to-end samples. Both exact manifests and operation identities match in every sample. Its 132 Qt sites and 289 HarfBuzz sites have complete collectors, while coverage remains false. The derived `qt-harfbuzz-tranche2-trigger-audit.json` distinguishes actual native invocations from entry-level conservative placeholders: each material sample reaches 100 single-character mappings, four string mappings, two single-glyph advance calls and 100 glyph-array advance calls. The four HarfBuzz unsupported calls are a shape-entry gap marker, not proof of four actual copies. These raw SDK byte facts remain outside contract sums until overlap with existing public upper bounds is resolved.

The third isolated tranche has actually compiled and installed 354 HarfBuzz sites. Fifteen original-versus-observed shaping cases still preserve every reported glyph field; six newly reached typed store sites produce 294 calls and 1,176 bytes of additional known writes in that independent probe. The separate Qt third prefix has 157 sites. It recompiles qglobal's manifest, CoreText adapter stores and Qt-to-HarfBuzz callback outputs, reusing 493 unchanged Release objects and hashing 5,977 frozen dependency headers. `object-reuse.json` records exact original/actual compiler and linker arguments; `-iquote` restores the moved source file's original implicit local-header lookup. Actual Core/Gui/HarfBuzz marker loading matches, and every first/second-prefix library hash remains unchanged. Native same-run measurements for the third prefix are still pending and cannot inherit the second prefix's pass.

The VTK AUTO slice observes deduplicated real coordinate uploads, original inverse-transform builds and original camera-shader calls. Its vector upper bound is 192 bytes per supported enabled AUTO upload; inverse-transform typed stores are bounded by 1,696 bytes per actual enabled build. The shifted float3 worker writes the same PackedVBO destination already charged by the existing two-write bound. Shader products, conversion and possible uniform-cache assignment are separate bounded stores. Alternate shift methods, nonidentity actors and environment shader matrices remain unknown. The real headless probe preserves AUTO enable/disable decisions, VBO modification times and inverse output; native operation-bound evidence is still pending. Exact source hashes/formulas are in `vtk-auto-shift-source-audit.json`.

`font-copy-remaining-source-inventory.json` lists specific unobserved HarfBuzz glyph aliases and field mutators. Further source/IR work must cover those stores and cache/container moves before the typed-store placeholder can be retired. Qt/HarfBuzz-owned character/glyph/advance/position/scratch buffers and caller-provided native outputs fall within the copy audit. Immutable font-file/table assets cannot automatically be labelled model payload, while CoreText's potentially copied model-derived input/temporary values cannot be guessed as zero. The public native API gives no internal capacity/copy-count bound. The existing Cocoa `fontengine=freetype` option is a concrete source-visible alternative to investigate with same-font glyph/metric/pixel and selection comparisons; it has not changed the default product or closed the default CoreText gap.
