# Finite Qt FT insertion-cache observations

The separate Qt7 diagnostic SDK closes the two actually reached insertion-cache boundaries from frozen Qt6: 705 glyph-data hash insertions and two missing-glyph-set insertions. Each original operation has one admission and one known completion callback. Completion requires the original call to return, exactly one compatible original Node action, and no type or observer-limit failure. The parents carry zero bytes. The default desktop backend, product sources, shared build configuration and older SDK prefixes were not changed. This is a finite SK-12 coverage diagnostic; formal whole-process copy coverage remains unknown.

The [report](qt-freetype-tranche7-report.json) binds source statements, manifests, commands, reused object hashes, runtime images and all raw evidence. The new preparation script retains Qt's original C++17/Release/ABI flags and adds only a private header search path to the FT translation unit. Core and FT are recompiled; 494 frozen objects are reused. The 309-site manifest adds 56 insertion-cache sites and keeps `coverage_complete=false`. The loader and actual native probe require one exact Qt prefix; unrelated hashes are inactive. Preparation refuses to overwrite an existing Qt7 prefix. The failed C++20-only observer preparation and its compile logs are retained separately; the repaired observer uses C++17 traits without changing SDK flags.

The SHA-bound `qhash.h` Node/Span/Data paths record actual original statements. Bulk copies use the original `memcpy` argument. Placement creation, detach and rehash record typed destination bounds, rather than allocated capacity. Scalar/default-member stores have distinct destinations. A relocation `memcpy` has no second per-field child charge. The FT key temporary is separate from the subsequently constructed map Node; existing FT6 bitmap/Glyph-object stores are separate from map key/pointer/index storage. Borrowed Bucket/iterator descriptors and unchanged shared-reference guards are not deep payload copies. Typed representation byte bounds are conservative source-level facts, not exact hardware memory traffic or allocator footprints.

The actual native 64-case run has 1,418 insertion-cache copy callbacks / 35,644 bytes and 6,019 write callbacks / 24,592 bytes, with no unsupported insertion-cache callbacks. Four actual Span storage relocations copied 4,608 bytes. Data rehash/shared detach were not reached by this font run and are not asserted to have run there. Separate headless cases reached real growth, rehash and Span relocation; shared detach copied each of 1,000 original Nodes once, 100 duplicate insertions only assigned the existing values, and two identical missing-set insertions preserved a one-entry set. A nontrivial QString key, a 32-byte observer budget and an operation with no Node action all remained unknown. An impossible `reserve(qsizetype::max)` request also executed Qt's original capacity guard and threw `std::bad_alloc`; the original empty hash remained empty. This allocation failure is separate from observer-budget exhaustion. The first headless run is retained alongside the final run.

All 64 input, metric and complete pixel records equal frozen Qt6. Thirty-four raw case objects are exactly equal. The other 30 keep their original hash-return-order differences: one explicit full-run original-index bijection simultaneously verifies all six parallel arrays, including engine identity, font-table hashes, glyph IDs, positions and source indexes. No field is dropped or silently normalized. These finite results do not establish Mac/FreeType equivalence or universal glyph support. Original warnings are retained.

The raw counters remain separate from formal end-to-end contract totals and public bounds. FreeType 2.14.3's own loader, renderer, outline/color/cache buffers are still unobserved. The Qt FT LCD converters (`convertRGBToARGB` / `_V`), outline/path operations (`addOutlineToPath` / `addGlyphsToPath`), transformed cache and non-insertion hash paths remain outside this slice. Other Qt/HB entry placeholders, default CoreText, and font-asset versus model-derived-input classification remain open. The next finite Qt source slice can cover the two actual LCD conversion loop destinations and transformed-cache initializers with branch-specific probes; outline/path work also needs its original QPainterPath container stores. None of these gaps is closed by zero callbacks.

Strict independent compilation, the actual headless and native runs, manifest/loader checks, original-output comparison, Python compilation, C++ formatting, design checks and `git diff --check` passed. After the preparation script was split into named header/compile/framework steps for readability, its replayed hash/header/helper bytes still exactly matched the linked SDK. The prefix is frozen for parent review and further isolated integration. No complete SK/P0 acceptance or performance pass is claimed.
