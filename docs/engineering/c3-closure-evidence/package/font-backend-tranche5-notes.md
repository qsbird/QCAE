# Qt 6.11.1 FreeType bitmap metrics diagnostic

This is an isolated diagnostic SDK and a finite behavior comparison. The product's default Cocoa/CoreText backend and the frozen Qt 3/3b/4 prefixes are unchanged. No complete process-copy coverage or SK/P0 acceptance is claimed.

The original FreeType `SFNS/14/emoji` case produced a white 1280×320 image at DPR 2. Its fallback bitmap font's real glyph images were nonempty. Apple Color Emoji uses a design UPEM of 800 but the selected FreeType bitmap strike has ppem 20. Qt's base height initializer combined the design HHEA metrics with this ppem, then applied its existing 34/64 bitmap scale. This gives the observed ascent 297.5 and descent 92.96875, placing the line below the original canvas. The original failure and all its glyph/bitmap facts remain archived in `font-backend-freetype-emoji-build36b.json` and `font-backend-freetype-emoji-causal-audit.json`.

`tests/prepare_c3_qt_freetype_metrics_tranche.py` prepares an independent tranche 5. Its only semantic change preserves the native selected-strike pixel height metrics for non-scalable FreeType faces; scalable faces still invoke the original base initializer. The original bitmap scaling, glyph rasterization, HarfBuzz shaping and `emSquareSize()` remain unchanged. The official Qt source archive, exact replacement, compiler/linker commands, ABI headers and 494 reused object hashes are bound in `font-backend-tranche5-diagnostic-report.json` and the ignored `build-c3-qt-observed/tranche5/object-reuse.json`. Only `qfontengine_ft.cpp` and the QtCore manifest object were rebuilt with two threads. The prepared prefix is now frozen; do not rerun its preparation script against it.

The unchanged strict probe ran sequentially against this SDK with the actual Cocoa Mac and FreeType engines. Both completed all 64 fixed cases. The corrected `SFNS/14/emoji` line has ascent 13.53125, descent 3.328125, height 17 and 1293 nonwhite pixels. All eight emoji cases now draw inside the unchanged canvas. Mac and FreeType are not equivalent: all 64 metric and pixel records differ. FreeType also emitted two internal glyph-65535 load warnings; no public run contained glyph 0 or 65535. The internal warning caller remains unproved and is not suppressed.

A separate frozen Qt4 Mac64 control distinguishes this patch from earlier SDK differences. Mac4 and Mac5 have identical metrics and full pixel records in all 64 cases. Thirty-five raw case records are exactly equal; the other 29 retain raw glyph-run ordering differences. Every complete glyph run has an exact index bijection across the two reports, including font identity, glyph IDs, source indexes, positions, advances and bounds. The official `QTextLayout::glyphRuns()` returns values from a hash keyed by engine pointer and flags. This source fact explains why raw list order is not a stable comparison contract; the raw exact comparisons remain false where different. No field is normalized to create an equivalence pass.

The installed SDK and frozen Qt4 control have different pixel records in all 64 cases despite identical metrics and an exact complete-run bijection in every case. These differences are preserved separately and are not attributed to the FreeType-only repair. The reports bind loaded image paths/hashes, OS, screen, font input hashes, fixed text and canvas. No general pixel-equivalence claim follows from these finite results.

The FreeType path is now usable for these 64 diagnostic cases. It is not a replacement acceptance environment. A next bounded slice can identify the internal glyph-65535 caller, then inventory Qt FreeType cache/glyph buffers and pinned FreeType 2.14.3 owned stores, including inline/indirect growth. The existing 157 Qt and 377 HarfBuzz sites retain incomplete-coverage flags and HarfBuzz shape-entry placeholders. Cocoa's font database still needs immutable font-asset versus model-derived UTF16/glyph-input classification. Default CoreText copies remain unknown, and any proposed environment change still requires a separate baseline decision and complete same-run desktop/selection/recovery evidence.
