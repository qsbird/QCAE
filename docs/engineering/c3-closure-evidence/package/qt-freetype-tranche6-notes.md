# Finite Qt FreeType stores and glyph-65535 causal diagnostic

The two observed FreeType warnings are advance queries for transient AAT ligature-component deletion markers, rather than final missing visible glyphs. The frozen Qt5 warning-stack probe executed the original fixed 64-case probe once, forwarded each original warning once and captured the real call chain: QTextLine layout → QTextEngine HarfBuzz shaping → glyph horizontal advances → Qt `recalcAdvances()` → FreeType `loadGlyph()`. It did not modify Qt5 or invoke a second draw to repair the result.

The independent Qt6 SDK adds a gated, always-true HarfBuzz message callback around the original single `hb_shape_full()` invocation. In the actual 14px and 18px Latin-combining inputs, the buffer immediately before each warning contains glyphs `[192,65535]` at source cluster 8 (`fi`). The final buffer contains `[192]`. HarfBuzz's AAT source defines 0xffff as `DELETED_GLYPH`, marks the ligature's consumed components and removes them after advance positioning on this path. The public run uniquely corresponding to these facts is the system-general-font Latin case's Helvetica run. No final public run contains glyph 0 or 65535. The original warnings remain in the logs; no FreeType call or warning was bypassed.

All 64 Qt6 inputs, metrics and full pixel records match frozen FT5, and all complete glyph-run payloads have exact original-index bijections.
