# M1 Nastran text subset

Status: declared local text codec, profile `qcae.nastran.linear-static` version `0.1.0`. The generated definition digest identifies this documented implementation. `configured=false` and `validated=false`: no solver executable or numerical acceptance evidence is bundled. This codec creates a candidate `Model` or an `ArtifactPlan` in memory. It does not read or write files, mutate an open document, or certify solver output.

The input is an explicit named text-resource bundle with a root resource, nonblank source-model ID, exact profile reference, and explicit unit system `mm-N-MPa`. Nastran decks do not encode units, so the codec never guesses. All paths are relative, canonical bundle paths. `INCLUDE 'relative/path.bdf'` is resolved relative to its containing resource. Absolute paths, traversal, aliases, cycles, repeated resources, missing resources and unreferenced bundle resources block import. Namespace numbering spans the whole bundle; INCLUDE does not create a new GRID or MAT1 number space. One root and its include tree are retained as `IncludeDocument` records, without invented parts.

| Segment/card | Accepted fields and constraints |
| --- | --- |
| Executive/case control | `SOL 101`, `CEND`, exactly `SUBCASE 1`, direct `SPC = SID` and `LOAD = SID`, `DISPLACEMENT = ALL`, `SPCFORCES = ALL`, `BEGIN BULK`, `ENDDATA`. One `SPC1` and one `FORCE`, both referenced. |
| GRID | `ID,CP,X,Y,Z,CD,PS,SEID`; CP/CD/PS/SEID blank or zero. Basic global Cartesian coordinates only. |
| CBAR | `EID,PID,GA,GB,X1,X2,X3`; vector orientation only, finite and nonparallel to the beam. No G0 orientation, offsets, pin releases, or extra fields. |
| PBAR | `PID,MID,A,I1,I2,J,NSM`; positive A/I1/I2/J, NSM blank or zero. Other section values, including K1/K2 and I12, remain blank; blank K1/K2 retain the MSC CBAR default of infinite transverse shear stiffness (zero shear flexibility). |
| MAT1 | `MID,E,G,NU`; positive E, finite `-1 < NU < 0.5`; G blank or exactly equal, as a parsed double, to `E/[2(1+NU)]`. A rounded explicit G is rejected because the model retains E and NU, not G. Remaining fields blank or zero. |
| FORCE | `SID,G,CID,F,N1,N2,N3`; CID blank or zero; one nonzero finite magnitude and direction, mapped to a global nodal force. |
| SPC1 | `SID,C,G1,...`; unique digits from 1–6 and explicit GRID numbers. `THRU` and continuation are unsupported. |

Only comma-separated, single-line free-field bulk cards of at most nine fields are accepted. SPC1 therefore has at most six GRID numbers in this slice. Numeric tokens are limited to eight characters; export searches for an exact round-trip decimal or exponent spelling and fails with `precision_unrepresentable` if none fits. `FORCE` exports magnitude 1.0 with direct global force components so normalization cannot introduce rounding. CBAR X1 must have a floating spelling (`0.0` or `0.`, for example), distinguishing vector orientation from integer G0. INCLUDE statements are at most 72 characters. Fixed format, continuations, inline comments, implicit Nastran exponents, unknown cards, unexpected control statements and unsupported nonblank fields are blocking issues. Full-line `$` comments are ignored; export normalizes comments, spelling and numeric formatting. Import checks forward references after all includes and runs domain validation before returning a candidate. A failed import or export returns no partial model or artifact. QCAE limits are 128 resources, depth 10, 1 MiB total text, 4096 characters per line and 100,000 physical records.

Stable imported entity IDs are scoped by source-model ID, card namespace and source number. `SourceIdentifier` keeps the source number and owning include. Export freezes a separate `ExportIdentifier` map: valid source numbers are reused independently by namespace, and new or conflicting numbers are assigned deterministically. New entities without source ownership go in the root resource. Export requires exactly one supported analysis and all FORCE/SPC1 physics selected; incomplete material NU and invalid model references block export. Parts, assemblies, sets and platform names have no BDF representation and are reported as nonblocking semantic loss. The artifact preserves include organization when safe. The caller must publish files atomically and bind the artifact to a transaction/history path; that is outside this codec.

The field semantics and case-control shape follow the [MSC Nastran 2022.1 Quick Reference Guide](https://documentation-be.hexagon.com/bundle/MSC_Nastran_2022.1_Quick_Reference_Guide/raw/resource/enus/MSC_Nastran_2022.1_Quick_Reference_Guide.pdf) and [MSC Nastran 2024.1 Linear Static Analysis User's Guide](https://documentation-be.hexagon.com/bundle/MSC_Nastran_2024.1_Linear_Static_Analysis_User_Guide/raw/resource/enus/MSC_Nastran_2024.1_Linear_Static_Analysis_User_Guide.pdf). The [MSC Nastran 2022.1 Getting Started Guide](https://documentation-be.hexagon.com/bundle/MSC_Nastran_2022.1_Getting_Started_Guide/raw/resource/enus/MSC_Nastran_2022.1_Getting_Started_Guide.pdf) documents eight-character free-field numeric behavior. The bundle path security policy and tighter syntax are QCAE choices. No actual MSC version or other Nastran dialect has been run against these artifacts yet.
