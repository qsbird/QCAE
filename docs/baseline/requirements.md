# QCAE 需求基线 1.0

状态：已收敛的开发设计基线；产品尚未实现，本文不代表功能或性能已经通过验收。

本文件确定 P0 范围，与[架构设计](../architecture/README.md)和[验收基线](acceptance.md)共同作为后续开发依据。早期 v0.1—v0.8 文档保留研究过程；范围或规则冲突时以本基线及同步更新的架构文档为准。

## 1. 产品边界

P0 是运行于本机、面向中小模型的 CAE 前处理平台。必要 GUI 与外部 AI 共用业务核心，实现一个受控 Nastran 一维悬臂梁分析闭环；优先做好实体关系、事务、恢复、查询和无界面接口。

- 领域与应用核心使用 C++20，不依赖界面、渲染、数据库或大模型实现。
- Qt 6 桌面端使用 VTK 显示派生数据；独立本地 `qcae-engine` 持有唯一活动模型和历史。
- 外部 AI 通过 MCP 桥调用同一引擎；CLI 和测试也通过业务契约执行，不使用模拟点击。
- SQLite 3 承担工作恢复库和工程快照持久化；模型事实不定义为数据库行或 VTK 对象。
- P0 先支持一份活动可编辑工程，可有 GUI、CLI 和多个 AI 连接；不扩展成协同编辑产品。
- 亿级、服务器部署是后续方向，不属于 P0 容量承诺。中小模型的实际分档由环境验证登记。

## 2. 功能与底层要求

需求 ID 固定用于任务、测试和变更追溯；修改说明或拆分需求时保留原 ID 的历史。

| ID | P0 要求 | 可验收边界 |
|---|---|---|
| REQ-01 | 必要工作区 | 一个主视口、组织浏览器、最小属性表单、任务/诊断/历史区及文件、编辑入口；业务能力不以菜单是否存在为完成标准 |
| REQ-02 | 统一业务接口 | GUI、CLI、MCP 调用相同操作；核心无需窗口或图形上下文即可读写、查询、修改、撤销、检查和求解 |
| REQ-03 | 稳定实体与组织关系 | 部件、装配层级、材料、属性、集合、INCLUDE 分别表达，支持多视角查询同一实体；内部 ID、求解器编号、存储位置、渲染 ID 分离 |
| REQ-04 | 引用与依赖 | 正反向引用查询、删除影响、共享属性影响、缺失引用诊断；合法提交中的模型与引用索引一致 |
| REQ-05 | 查询与精确选择 | 明确候选范围的条件组合、点选、框选、条件批选、穿透、包含隐藏、反选及集合运算，结果定位真实实体并绑定版本 |
| REQ-06 | 基础显示 | 相机旋转/平移/缩放、适应窗口、线/面、颜色、高亮、显隐与隔离；显示状态独立于分析输入，可丢弃缓存重建 |
| REQ-07 | 最小分析模型 | 创建或导入受控一维梁，编辑所需材料、截面、载荷、约束和工况；有字段类型、单位和局部方向，不实现通用复杂表格 |
| REQ-08 | 工程与格式 | 新建、打开、保存、另存、放弃修改；`.qcae` 保留平台语义，Nastran 只承诺明确子集的语义往返和 INCLUDE 组织 |
| REQ-09 | 原子修改与历史 | 全部正式编辑走统一提交链；批量操作整体成败；GUI/AI 共用线性 undo/redo，准确恢复数值、实体和引用 |
| REQ-10 | 持久化与恢复 | 工作恢复库与手动保存快照分开；恢复已确认持久化提交和有限历史，识别未完成任务，可靠处理保存中断与放弃修改 |
| REQ-11 | 任务与资源 | 明确任务状态机、取消边界、冻结输入、版本校验；控制缓冲、历史、任务并发、临时磁盘等可计量资源 |
| REQ-12 | 检查与问题定位 | 提交前检查不变量；基础模型/分析检查返回实体、规则、严重度和输入版本；修复仍通过命令，过期诊断有标识 |
| REQ-13 | 真实求解与结果 | 固定输入及运行目录，启动一个已有 Nastran 求解器，读取位移与反力并验证；分别记录执行、解析、检查状态 |
| REQ-14 | AI 语义与工程引导 | 外部 AI 完成限定悬臂梁的澄清、预览、修改、检查、求解、解释；缺必要物理事实返回待输入，结果保留假设与证据 |
| REQ-15 | 版本、幂等与人机交替 | 文档身份/激活代号/修订检查；同操作重试不重复提交，同键异参拒绝；创建/打开也有宿主级幂等记录，未知文档ID时可查回结果；重连可查询原操作事实与当前状态 |
| REQ-16 | 可发现的操作契约 | `OperationDescriptor` 统一定义类型、单位、参数、前置条件、错误、副作用和结果；为 GUI/CLI/AI 生成一致说明，P1 脚本沿用此接口 |
| REQ-17 | 引擎与工程生命周期 | 唯一本地业务宿主、工程写锁、连接发现和重连；GUI 关闭不隐式终止任务，MCP 桥不创建第二份模型 |
| REQ-18 | 交换能力与变化影响 | `ImportReport/ExportReport` 报告支持范围、缺失/未支持内容、编号映射及语义损失；`ChangeImpact` 按引用传播区分组织、引用、显示和分析输入的失效影响，不新增通用模块框架 |

## 3. 组织与选择的确定语义

装配在 P0 表示真实部件的层级组织，不包括同一部件多个变换实例。节点可被不同部件的单元共享，不为树形组织复制节点。

集合为明确实体成员的快照；实体可进入多个集合。保存查询结果形成成员快照，不引入动态规则集合。INCLUDE 表达文件包含关系及实体来源，不替代部件或装配。

查询条件限定为实体类型、ID/范围、名称、部件/装配、集合、INCLUDE、材料/属性及支持字段、可见性与框选空间条件；支持 AND/OR/NOT 和交并差，不开放任意 SQL 或表达式写模型。

- 隐藏是主动关闭显示；遮挡是对象仍显示但在前方对象之后，二者独立。
- 穿透忽略遮挡；是否包含隐藏对象使用独立选项，不能隐式混同。
- 框选声明完全包含/相交、相机和投影；反选声明候选范围和实体类型。
- 选择与预览绑定 `DocumentId / DocumentEpoch / Revision`；过期则重建，不能静默作用于新对象。
- 一个实体可以映射多个显示三角形，最终命中合并回真实实体；显示三角形不得进入物理模型。
- 没有图形能力时，精确可见性选择返回能力不可用，不自动降级成穿透；普通数值查询仍可执行。

## 4. 修改、保存与恢复合同

一次正式修改先准备完整候选状态、引用和历史，再在文档单写队列中校验版本。工作库原子写入模型、历史、修订、幂等结果及关联任务提交事实，随后发布 RAM 状态。

成功响应表示达到已声明的持久化边界。提交结果不确定时先核对事实，不能重新执行；显示缓存或通知失败不回滚已经提交的业务状态。

Undo/redo 通过相同提交路径产生新修订；恢复准确旧值而非猜测逆算法。新编辑剪除 redo 分支时，仍保留幂等保证期内的原操作记录。模型历史与临时选择/相机状态分别管理。

P0 保留**有限、持久化的线性历史**：故障恢复后可在保留窗口内继续撤销/重做。条数/字节上限、裁剪规则和幂等保留期在持久化原型固定，并通过接口可查询；超出窗口明确不可撤销，不承诺无限历史。

| 标识/状态 | 规则 |
|---|---|
| `ProjectId` | 已保存工程身份；另存建立新身份并记录来源，不单独用作文件锁 |
| `DocumentId` | 工作文档/恢复库身份；正常从工程创建工作副本时新建，故障恢复原工作库时保留 |
| `DocumentEpoch` | 每次打开或恢复激活都更新；旧代号不能直接提交，需查询旧操作事实并重新取得状态 |
| `Revision` | 单调提交序号，undo/redo 也递增，不因内容回到过去而回退 |
| `ContentStateId` | 业务内容状态，用于保存点和 dirty 判定；不把相机、保存路径视为物理修改 |
| `.qcae` 与工作库 | 前者只在明确保存/另存时更新；后者记录当前已提交工作，不能将自动恢复等同手动保存 |

保存生成一致临时快照并验证后发布；目标替换与工作库保存标记之间的中断靠保存意图及内容身份核实。另存不增加模型修订或模型历史；原任务继续引用原冻结输入与运行目录。

放弃修改是明确操作，不能在下次启动又自动恢复已放弃的工作。未终止任务所属工作库和资源保留到终态；旧任务不能写入重新打开的活动文档。

## 5. 任务与 AI 的最小闭环

任务区分排队、运行、取消请求、提交、成功、失败、已取消、中断以及必要的待核实状态。取消请求不代表已经取消；短暂原子提交区完成后报告真实结果。P0 支持识别中断并重新运行，不支持算法中途续算。

任务只读冻结输入，产生候选变更或独立产物；模型提交仍校验文档身份、激活代号和修订。求解旧快照可以完成，但结果明确属于旧输入，不冒充当前结果。

限定场景：等截面直梁、线弹性、小变形静力、一端固定、端部横向集中力。最小卡片候选是 GRID、CBAR/PBAR、MAT1、SPC1、FORCE 和必要控制段；以选定方言的能力清单及真实求解验证最终落实。

AI 负责语言交互和操作组织，确定性场景规则在核心。流程为补齐单位与工程事实 → 固定假设 → 预览影响 → 原子建模/修改 → 检查 → 求解 → 数值核验 → 带依据解释。

常规已授权可逆操作不强制逐次确认；必要事实缺失、方向歧义或超出场景必须返回待输入/不支持。AI 不直接执行任意 shell、SQL 或绕过核心改文件。

## 6. 非目标与后续边界

- 不实现服务器大模型、远程渲染、亿级验收、分布式计算或多人协同。
- 不实现多求解器模板、任意 Nastran 卡片兼容、通用后处理或自研求解器。
- 不增加完整 CAD、自动网格、局部重网格、装配实例系统；需要时再接入已有组件。
- 不实现复杂表格、内置聊天、通用智能体/工作流框架、企业数据管理或完整插件生态。
- 不承诺算法断点续算、无限历史、外部进程恰好启动一次或同进程第三方分配的硬内存隔离。
- P1 才交付脚本/扩展用户功能；P0 只落实支持它们的业务接口，不交付脚本编辑器或录制器。

以下是环境和参数登记项，不阻止核心设计或无界面基础开发；没有证据时保持未完成，不虚构默认验收配置。

| 图形后端 | VTK 渲染/拾取可用配置；无窗口数值链与图形能力分别验证 |

具体验证映射见[验收基线](acceptance.md)。参数固定后，仅将非敏感版本、支持矩阵、夹具、容差与配置模板纳入版本控制；真实机器路径、凭据和私有环境配置保持本地并被忽略。不将尚未测量的容量、FPS 或 token 预算当成功能承诺。
