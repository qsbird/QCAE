# QCAE 设计基线 1.1

状态：本轮确定的开发基线；完整P0尚未实现；M0/M1进展见[运行记录](../implementation/m0.md)与[文档/格式实现](../implementation/m1.md)。此文将v0.1—v0.8讨论中已选择的方向收敛为当前依据，后续架构变更通过ADR记录。

## 确定决策

| 项目 | 基线决定 |
|---|---|
| 产品范围 | 本地中小规模CAE前处理P0，底层能力优先；亿级作为后续目标 |
| 分析范围 | 单一Nastran受控子集，一维线性静力悬臂梁；已有外部求解器完成真实验证 |
| 核心语言 | C++20；领域、契约及业务服务不依赖界面/存储/AI SDK |
| 人机入口 | Qt 6桌面GUI；外部AI客户端通过MCP工具桥；无界面CLI/测试入口 |
| 业务宿主 | 独立本地qcae-engine，单文档单提交者，一套状态和undo历史 |
| 通信 | 本地IPC，显式身份、版本、结构化参数/错误，批量数据通道 |
| 显示 | VTK消费公共RenderPacket；engine侧只生成显示数据，不加载图形上下文 |
| 持久化 | SQLite 3工作恢复库＋明确保存的.qcae工程快照＋RAM已提交表示 |
| 历史 | 有配额的线性持久历史；undo/redo也走事务并产生新修订 |
| AI | 外部AI理解和编排；核心执行校验、事务与数值流程；不做内置聊天 |
| 脚本 | P0可调用契约和CLI；面向用户的脚本运行时/扩展为P1 |
| 几何与网格库 | 保留适配边界；P0直接创建/导入梁模型，无实际用例前不接入CAD/自动网格引擎 |

求解器扩展结构按[能力包补充](../architecture/solver-profiles.md)确定：公共机制/物理语义共享、专有字段受控、分析目标显式、来源与导出编号分离。当前仍仅实现一个Nastran包。

P0装配为部件层级组织；重复变换实例、复杂CAD/网格、完整后处理、多模板、多人共同编辑和远程部署均不包含。

## 必须保留的产品能力

部件/装配、材料/属性、集合、INCLUDE多视角；条件查询、框选、批量选择、隐藏/穿透及反选；基础显示与悬臂梁参数编辑；引用检查；保存/另存与格式交换；undo/redo；任务状态、取消、版本、资源配额、恢复；GUI与外部AI共享上述能力。

详见 [需求](requirements.md)、[架构](../architecture/README.md)、[接口契约](../contracts/README.md) 和 [验收](acceptance.md)。

## 参考研究正式吸收的三项设计

1. **OperationDescriptor**：一个操作定义承载参数、单位、前置条件、输出、错误和副作用。能力发现、MCP说明、CLI帮助及契约测试从它获取信息。
2. **ImportReport / ExportReport**：格式适配显式报告支持/遗漏/编号映射和语义损失。未知或无法保持正确的输入不能静默转换。
3. **ChangeImpact**：结合字段和引用关系判断模型、分析输入、检查和显示的失效范围。集合被载荷引用时，其成员变化也影响分析。

这些落在现有模块，不新增大型框架。Gmsh同步不是平台提交，脚本回放不是undo，SQLite事务不是外部文件原子发布，求解器退出成功不是结果核验通过。

## 环境配置不伪装成已验证事实

架构已确定；以下是实施门禁，不能凭空填写为已通过：

- M0记录实际OS、编译器、Qt/VTK/SQLite兼容版本及IPC路径。
- M1锁定目标Nastran方言的受控卡片/语法支持矩阵。
- M2设置历史、内存、临时目录配额及恢复保留策略。
- M3定义中小模型分档、图形后端、硬件与响应性基准。
- M4配置真实Nastran可执行程序和数值验收夹具；没有求解器则该验收未完成。
- M5配置一个实际外部AI客户端及模型，记录数据去向和接入证据。

这些配置不能阻止先执行M0的可完成部分；也不能被模拟结果替代。
